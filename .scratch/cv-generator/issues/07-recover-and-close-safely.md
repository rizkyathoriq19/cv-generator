# 07 — Recover saved CVs and close safely after storage failures

**What to build:** A job seeker recovers saved work from a rolling previous revision, retains unsaved edits after storage errors, chooses how to close safely, and avoids concurrent application instances overwriting projects.

**Blocked by:** 06 — Export and safely import independent project backups.

**Status:** implemented and application-verified on Arch/Omarchy (isolated library; the window close was requested as `WM_DELETE_WINDOW` because Xvfb has no window manager). Evidence: [ticket 07 evidence](../evidence/ticket07/README.md).

**Story coverage:** US-38, US-39, US-40, US-41, US-42, US-59.

- [x] Retain exactly one rolling previous valid saved revision using a replacement sequence that preserves recoverability; do not promise full history or zero loss of not-yet-saved edits.
  - Evidence: `each_save_keeps_exactly_one_previous_valid_revision` (a third save leaves only the second in `<id>.prev.json`), `a_denied_save_keeps_the_current_and_previous_revisions`, `an_interrupted_replacement_leaves_the_last_saved_revision_readable`, `a_corrupt_current_file_never_replaces_the_previous_valid_revision`. App run: `t07source.json` + `t07source.prev.json` after the first autosave (1,736 / 1,725 bytes); the notice states one previous revision, not full history. Not-yet-saved edits are explicitly not recoverable.
- [x] Detect current-file corruption, preserve the corrupted evidence rather than silently overwrite it, and recover a valid previous revision with an explicit notice. If neither is valid, report the condition without fabricating or blanking the CV.
  - Evidence: `a_damaged_current_file_recovers_the_previous_revision_and_keeps_the_evidence` (corrupt bytes preserved and named in the notice; the current file is restored byte-identically), `a_damaged_project_with_no_valid_previous_revision_is_reported_and_left_alone` (library snapshot byte-identical after the failed open), `preserving_damage_keeps_the_current_file_in_place` (a failed recovery write cannot unlist the CV), `damage_found_during_a_save_is_preserved` + `a_save_reports_the_damage_it_preserved` (damage found mid-edit is kept and reported, never silently replaced), `a_newer_project_file_is_refused_and_left_alone`, `a_foreign_project_file_is_refused_without_rewriting`, `a_save_never_overwrites_a_refused_project_file` (refused files are reported, never quarantined, rolled back, or overwritten), `the_library_lists_a_damaged_project_so_it_can_be_recovered`. App run: row `Recovery demo · Damaged`, notice naming `t07source.corrupt-1794882427265315398.json` (41 bytes unchanged), current restored byte-identically; with the CV open, replacing the current file and editing produced `Tersimpan` plus the notice naming `t07source.corrupt-1794886797966265268.json` (step 25). The both-revisions-damaged report and the refused-file paths are proven at the Rust seam only, not clicked through the UI.
- [x] On a failed save, keep current edits in memory, show a persistent Save failed state, and support retry or exporting the current project backup through the existing transfer workflow.
  - Evidence: app run with `chmod 500` on the library: the header `Save failed` stayed until the retry succeeded, the dialog kept the unsaved edit, and `Export project backup…` wrote `Synthetic Candidate-backup.json` (1,785 bytes) while the project stayed unsaved. `a_denied_save_keeps_the_current_and_previous_revisions` proves a denied write leaves the library unchanged.
- [x] Normal close immediately saves pending changes. On failure provide Retry / Export backup / Discard and close / Cancel; only explicit discard may abandon unsaved changes. Successful backup export and saving the working project remain distinct.
  - Evidence: `Library` with a failed save opened the four-choice dialog; `Cancel` retained the edit; `Retry save` after restoring permissions wrote it; `Discard and close` left `t07source.json` byte-identical to before that edit. A window close (`WM_DELETE_WINDOW`) with a failed save kept the window open with the same dialog; with writes allowed it flushed and closed. The dialog showed `Backup saved: 1785 bytes → …` beside `Save failed`, and an export into the read-only folder showed `penulisan berkas gagal: Permission denied (os error 13)` without clearing the failure.
- [x] Enforce one application instance and one active CV editor so normal use cannot race two writers against the same library.
  - Evidence: `one_running_instance_holds_the_library` (the second `try_lock` fails; the lock is released on drop). App run: a second launch exited `1` with `Another CV Generator window is already open…` and only one window remained. The single editor is structural: the library and editor are mutually exclusive views over one `doc` state.
- [x] Use deterministic test-only failure controls to exercise denied writes, interrupted replacement, corrupt current/previous revisions, pending close, cancelled close, and backup-export failure; assert observable preservation and notices.
  - Evidence: `Faults { deny_write, interrupt_replace }` is passed only by checks (`a_denied_save…`, `an_interrupted_replacement…`); corrupt current/previous cases are written directly (`a_damaged_project_with_no_valid_previous_revision…`, `a_corrupt_current_file_never_replaces…`); pending close, cancelled close, and backup-export failure were exercised in the app run (`chmod 500` for a real EACCES, dialog `Cancel`, and an export into the read-only folder).
- [x] Demonstrate recovery/restart and each close choice in the running application, with accurate save indicators and controls/errors covered by the shared interface languages.
  - Evidence: recovery + restart and every close choice are recorded in [ticket 07 evidence](../evidence/ticket07/README.md) (steps 1–10); the Indonesian run shows `Rusak`, the Indonesian recovery notice, the localized close dialog (`Perubahan belum tersimpan tidak dapat disimpan`, `Buang dan tutup`, `Batal`), and the localized backup write error. The window close was requested as `WM_DELETE_WINDOW`; no window manager exists under Xvfb, so no title-bar button was clicked.
